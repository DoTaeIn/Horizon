# 경계 ROI와 연속 이동 로딩 감사

Claude Opus 5가 영역 로더와 이동 측정 테스트를, Sonnet 5가 영역 테스트와 이동 측정 CLI·문서를 작성했다. Codex는 코드 감사, 수정 요청, 실행 및 독립 검산과 이 감사 기록만 담당했다.

## 구현과 측정 범위

- `horizon/town_region.py`의 `load_region(path, region, mode)`는 임의의 양수·맵 내부 사각형을 반환한다. 겹치는 청크만 읽고 풀어 교차 영역을 정확히 합성한다. 한 픽셀, 큰 ROI, 직사각형 맵과 작은 끝 청크도 지원한다.
- 매 요청마다 파일 열기, 헤더와 전체 인덱스 읽기·검증, 선택 청크 읽기, 파일 닫기, 압축 해제·체크섬·합성을 측정한다. 1024 맵의 인덱스 메타데이터는 536바이트다. 전체 비교군은 매번 전체 파일을 읽고 풀어 같은 ROI를 복사한다.
- 원본 합성 마을·도로 높이맵 1024×1024, 청크 256×256, 시야 256×256. 두 시드 20261012·20261013, 세 코덱, 두 I/O 모드, 경로별 120단계×3회. 총 25,920회 로딩 결과를 매번 원본과 비교했다.
- 응용 프로그램 캐시와 미리 가져오기는 양쪽 모두 없다. 반복 위치도 다시 읽고 압축을 푼다. OS 캐시를 덥히는 읽기는 warm 모드의 각 경로 반복 시작 전에 두 파일에 한 번씩만 수행하며 측정에서 제외한다.
- 입력 좌표를 연속 재생하는 로더 테스트다. 렌더러·물리·비동기 스케줄링을 포함한 게임 프레임 측정이 아니며, 경로 총 시간은 로더 시간의 합이다. 두 비교군은 매 단계 번갈아 실행한다. 검증과 보고서 작성은 측정 밖이다.

## 감사 결과

- 전체 자동 테스트 300개: 295개 통과, 환경별 5개 건너뛰기. 기존 동작도 유지했다.
- 별도로 513×769 직사각형 맵에서 세 코덱마다 무작위 ROI 150개, 총 450개를 검산했다. 값·타입·소유 배열·연속 배치·교차 청크 개수·정확한 읽기 바이트·호출 수가 모두 일치했다.
- 두 보고서의 25,920회 원시 측정에서 `total_ns = read_ns + decode_ns`, 좌표와 ROI, 선택 청크, 요청·읽기 바이트, 읽기·seek 횟수, 교대 순서를 독립 계산했다. 중앙값·선형 보간 p95·최대·경로별 시간 합·읽기량 합·청크 분포를 다시 계산해 일치함을 확인했다.
- 입력 맵을 다시 생성하여 해시를 확인했다. 모든 컨테이너 파일의 준비 시점 해시·측정 전후 해시·실제 파일 해시가 같았고, 보고서의 실행 소스 해시는 현재 코드와 일치했다.
- 초기 경계 왕복은 캐릭터 중심만 경계를 넘고 선택 청크 집합이 바뀌지 않았다. 감사에서 반려해 시야 원점이 경계를 넘도록 고쳤다. 추가 감사에서 최대 481픽셀 왕복을 발견해 최대 28픽셀로 제한했다. 두 시드 모두 119/119 이동에서 청크 집합이 바뀐다.

## 해석과 제한

- 읽기량은 Python의 실제 요청·반환 바이트다. 물리 SSD 전송량을 측정한 것이 아니다. `macos_nocache`는 파일 디스크립터별 F_NOCACHE 요청이며 이미 캐시된 페이지 제거·SSD 캐시 우회를 검증하지 않았다. 물리적인 cold read라고 해석하지 않는다.
- 256×256 시야는 위치에 따라 1·2·4청크를 덮는다. 맵 가장자리에서 시야를 맵 안으로 이동시키므로 걷기와 순간이동에는 한 청크 요청도 포함된다. 경계 왕복은 두 시드에서 모두 네 청크를 읽으며 매번 집합이 달라진다.
- 시야가 맵 대부분을 덮으면 부분 로딩의 이점이 사라질 수 있다. 513 크기 테스트에서는 네 청크의 헤더·인덱스와 독립 압축 비용 때문에 부분 읽기량이 전체 파일보다 커지는 경우도 확인했다.
- 파일 형식은 기존 실험용 HCIX이며 인덱스 자체의 체크섬은 없다. 전체 인덱스 구조와 읽은 청크의 무결성을 검사하지만 읽지 않은 청크 본문의 손상을 탐지하지는 않는다.
- 비교군·반복의 순서는 교대하지만 코덱과 I/O 모드의 바깥 실행 순서는 고정이다. 측정값은 이 컴퓨터와 이 합성 높이맵에 한정된다.
- 다음 성능 단계는 이동 간 겹치는 청크를 재사용하는 제한된 캐시다. 그때는 전체 맵을 한 번 풀어 보관하는 비교군도 함께 두고 초기 로딩·최대 메모리·캐시 미스 지연을 따로 비교해야 한다.

## 파일과 재실행

- 로더: `horizon/town_region.py`
- 이동 측정: `scripts/compare_town_movement.py`
- 방법: `docs/town-movement-method.md`
- 원시 측정: `benchmarks/town-movement-1024-v1.json`, `benchmarks/town-movement-1024-seed2-v1.json`
- 독립 감사: `benchmarks/audit_town_movement.py`, `benchmarks/town-movement-audit-evidence.json`
- 실제 컨테이너: `data/terrain-local/town-movement-1024-v1/`, `data/terrain-local/town-movement-1024-seed2-v1/` (ignored)

```sh
.venv/bin/python scripts/compare_town_movement.py --size 1024 --seed 20261012 --steps 120 --repeats 3 --output /tmp/town-movement-new.json --containers-dir /tmp/town-movement-new-containers
PYTHONPATH=. .venv/bin/python benchmarks/audit_town_movement.py
```

CLI 출력과 컨테이너 디렉터리는 새 경로여야 한다. 감사 스크립트는 위의 기존 두 보고서와 로컬 컨테이너를 읽고 감사 evidence JSON을 다시 쓴다.
